Problem Formulation & Industry Context

Thermal Management Challenges in Industrial IoT

Current Embedded Vulnerabilities

  • Unsafe Direct Hardware Probing: Ad-hoc user-space scripts accessing I/O memory without kernel mutual exclusion cause bus deadlocks.
  • Kernel Floating-Point Traps: Executing IEEE-754 floating-point math inside Ring 0 corrupts process state because x86 kernels do not save FPU registers on traps.
  • Severe Alert Fatigue: Polling engines without hysteresis flood operators with duplicate alerts when temperature fluctuates at the trip boundary.
  • Monolithic Coupling: User applications tightly wired to register addresses must be completely rewritten on hardware sensor revisions.

The LTempGuard Architectural Solution

  • POSIX Character Device Driver: Sensor hardware encapsulated behind standard /dev/temp_sensor VFS contract (open/read/write/ioctl).
  • Integer Millicelsius Arithmetic: Zero kernel floats; all temperature processing uses fixed-point integer millicelsius (25,000 m°C = 25.0°C).
  • Edge-Triggered Hysteresis State Machine: Alerts dispatch strictly upon boundary transitions (NORMAL, WARNING, CRITICAL).
  • RAII Modern C++20 User Space: Safe file descriptor wrappers, zero raw owning pointers, and synchronized dual-sink text/CSV telemetry.

Ring 0 Implementation & Safety

Linux Character Device Driver Mechanics

Dynamic Allocation & Lifecycle

  • alloc_chrdev_region(): Dynamically allocates Major 240, Minor 0, preventing static driver number collisions.
  • cdev_init() & cdev_add(): Binds driver to the VFS dispatch table.
  • Sysfs & Devtmpfs Integration: Automatically registers temp_sensor_class and creates node /dev/temp_sensor (0666).
  • Zero Resource Leaks: Module exit unregisters cdev, destroys class, and releases dev number cleanly.

Kernel Concurrency & Isolation

  • Input Sanitization: Validates input boundaries (-40°C to +125°C); corrupt strings return -EINVAL.
Interface Control Document

VFS Operations & Shared IOCTL ABI

VFS Operations Dispatch Table

  • .open = temp_driver_open: Increments ref count and records caller PID.
  • .read = temp_driver_read: Formats millicelsius to ASCII and copies to user buffer.
  • .write = temp_driver_write: Parses input string, updates sensor register.
  • .unlocked_ioctl = temp_driver_ioctl: Direct binary ioctl dispatch.
  • .release = temp_driver_release: Decrements ref count.

IOCTL Commands (temp_ioctl.h)

  • TEMP_IOCTL_GET_TEMP (_IOR): Fetches atomic integer millicelsius in a single syscall.
  • TEMP_IOCTL_SET_TEMP (_IOW): Direct binary temperature injection.
  • TEMP_IOCTL_RESET (_IO): Resets sensor to factory 25.0°C.
  • TEMP_IOCTL_GET_STATUS (_IOR): Fetches full struct temp_status_data with trip status and kernel uptime.
#define TEMP_IOCTL_MAGIC 'T'
#define TEMP_IOCTL_GET_TEMP _IOR(TEMP_IOCTL_MAGIC, 1, int32_t)
#define TEMP_IOCTL_SET_TEMP _IOW(TEMP_IOCTL_MAGIC, 2, int32_t)
#define TEMP_IOCTL_RESET _IO(TEMP_IOCTL_MAGIC, 3)
#define TEMP_IOCTL_GET_STATUS _IOR(TEMP_IOCTL_MAGIC, 4, struct temp_status_data)

Edge-Triggered Analytics

Finite State Machine & Anti-Flapping Engine

State Transition Classification

  • NORMAL (< 40.0°C): Nominal temperature band. Displayed in green; no alerts fired.
  • WARNING (40.0°C - 59.9°C): Thermal stress band. Dispatches yellow alert banner.
  • CRITICAL (≥ 60.0°C): Dangerous overheat condition. Dispatches flashing red emergency alert.
  • Hysteresis Recovery: Safe cool-down back to NORMAL triggers confirmation alert.

Deduplication & Anti-Flapping

  • Edge-Triggered Logic: Alerts fire ONLY when previous_state != current_state.
  • No Operator Spam: Hovering around 40.0°C (e.g. 40.1°C, 40.2°C) will not re-trigger alerts.
  • Time-Sliding Deduplication: Suppresses identical alert payloads within sliding intervals.
  • Complete Forensic Audit: Even when visual alerts are suppressed, every sample is recorded to CSV.

Engineering Deep-Dive

Technical Breakthrough: WSL2 Kernel BTF Alignment

The Relocation Bug

  • Error: module: x86/modules: Invalid relocation target, existing value is nonzero for type 1, loc 000000004a3e0575, val ffffffffc0775730.
  • Type 1 is R_X86_64_64. Kernel module loader strictly mandates target memory loc to be zero prior to relocation.
  • Target memory in the binary on disk was confirmed zero, yet kernel memory at loc was non-zero!

Root Cause & Architectural Resolution

  • Root Cause: Running kernel had CONFIG_DEBUG_INFO_BTF_MODULES=y (adding 16 bytes: btf_data_size & btf_data to struct module).
  • In the build environment, missing pahole disabled BTF in Kconfig, shifting struct module offsets by exactly 16 bytes!
  • module_unload_init() wrote source_list pointers into the 16-byte shifted location where the module expected exit!
  • The Fix: Installed pahole, synchronized config from /proc/config.gz, compiled with gcc-11. Module loaded instantly!
